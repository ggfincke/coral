# Coral Python SDK (`coral exec`)

Unpublished local package (`packages/coral-sdk`). It is **not** a uv workspace
member of the repo-root `coral-dev-tools` project, and it is not published to
PyPI. This SDK speaks `coral exec` result `version: 1`.

It drives **one** headless Agent turn through `coral exec --output-format
stream-json`. Types stay transport-agnostic (subprocess now; a serve transport
can back the same `CoralClient` later). Event models are vendored from
`protocol/generated/python/exec_events.py` (regenerated by `npm run
protocol:gen`). Do not hand-write replacements.

Install from this directory:

```bash
uv sync
```

Requires CPython **3.14+** (not free-threaded `3.14t`) and, to actually spawn
exec, Node **>= 24**.

## Usage

Async-first:

```python
from coral_sdk import CoralClient

async def main() -> None:
    client = CoralClient(model="gemma4:31b-mlx")
    async with client:
        async for event in client.stream("summarize README.md"):
            print(event)
        result = await client.run("summarize README.md")
        print(result.status, result.response)
```

Sync wrapper (dedicated event loop; does not reimplement transport):

```python
from coral_sdk import CoralClient

with CoralClient.sync(model="gemma4:31b-mlx") as client:
    result = client.run("summarize README.md")
```

`stream()` and `run()` each spawn a **new** `coral exec` process. Exec never
resumes a session.

### Constructor

| Param                | Maps to                                                                       |
| -------------------- | ----------------------------------------------------------------------------- |
| `model`              | `-m` / `--model` (required)                                                   |
| `cwd`                | `--cwd` (defaults to the SDK process cwd)                                     |
| `host`               | `--host` (Ollama URL; exec canonicalizes)                                     |
| `permission_profile` | `--permission-profile` `read-only` \| `workspace-write` (default `read-only`) |
| `mcp`                | `--mcp` / `--no-mcp` (default off)                                            |
| `output`             | always `stream-json`; other values raise `CoralUsageError`                    |
| `result_file`        | `--result-file`                                                               |
| `prompt_file`        | `True` / a path / auto when the prompt is large                               |
| `bin`                | executable override; else `CORAL_BIN`                                         |

### Binary discovery

1. Constructor `bin`
2. `CORAL_BIN`
3. `coral` on `PATH`
4. Trusted package-relative checkout: `node dist/cli/main.js` (after `npm run build`)
5. That checkout's source through an existing `tsx` on `PATH` or its local
   `node_modules/.bin/tsx`

Discovery never searches the caller's cwd and never downloads tooling. Argv is
always an array, never a shell string.

### Usage split (do not normalize away)

| Channel                 | Type         | Shape                                     |
| ----------------------- | ------------ | ----------------------------------------- |
| stream `usage` event    | `TokenUsage` | camelCase Agent usage (`promptTokens`, …) |
| terminal `result.usage` | `Usage`      | snake_case four fields only               |

Unknown event `type` values fail closed (`CoralProtocolError`).

### Errors

| Class                 | When                                                                 |
| --------------------- | -------------------------------------------------------------------- |
| `CoralUsageError`     | exit 2, empty prompt, both prompt sources, bad cwd/model, over 1 MiB |
| `CoralFailedError`    | `status: failed` or exit 1                                           |
| `CoralCancelledError` | `status: cancelled` or 130/143 **without** a forced failed result    |
| `CoralProtocolError`  | malformed NDJSON, unknown `type`, missing terminal result            |
| `CoralBinaryError`    | coral/node not found, spawn failure                                  |

**runError beats cancel:** a result-file write failure forces `status: failed`
and exit 1 even after SIGINT. The SDK raises `CoralFailedError` from
`result.status`, not 130.

Prompt cap is **1,048,576** bytes, enforced before spawn. Small prompts go as
the positional argv entry; larger ones (or `prompt_file=True`) write a UTF-8
temp file and pass `--prompt-file`.

## What this SDK must not assume

- Multi-turn / session resume. Exec is one ephemeral turn and does not write
  `CORAL_HOME/sessions/`. `--ephemeral` is unused.
- Interactive approvals. Exec rejects every approval prompt. Profiles force
  listed tools to `always_allow`; anything else is rejected. Not a sandbox:
  `bash` still runs on the host.
- Events `onVerification`, `onAttachments`, `onCompaction*` — exec does not
  emit them.
- MCP enabled by default. It is off unless `mcp=True`; `--mcp` still
  fail-closes approvals.
- Git mutation, `task`, or `todo_write` in either profile. They are excluded.

`read-only`: `read_file`, `grep`, `glob`, `list_files`, `search_code`, `skill`,
`code_intel`, `git_status`, `git_diff`, `git_log`.

`workspace-write`: those plus `write_file`, `edit_file`, `bash`.

## Tests

From this directory, after `uv sync`:

```bash
uv run python -m unittest discover -s tests -v
```

Unit tests use recorded NDJSON and do **not** need a coral binary. Golden
fixtures load `protocol/fixtures/` through the Pydantic models.

One cross-language integration test spawns real `coral exec` against a stub
Ollama HTTP server. It is **skipped** unless `CORAL_BIN` is set:

```bash
npm run build
export CORAL_BIN="$PWD/dist/cli/main.js"   # from the coral repo root
cd packages/coral-sdk
uv run python -m unittest discover -s tests -v
```

`npm test` at the repo root stays uv-free and does not run these tests.
