# Coral repository guide

Coral is a local-first TypeScript CLI/TUI coding agent with optional hosted
providers. Keep changes scoped and preserve existing ownership boundaries.
Read `AGENTS.md` on demand for architecture and subsystem guidance before
changing those boundaries; it is not loaded alongside this file.

## Build and test

Use Node.js 24+ and npm from the repository root. Python development tools
use uv with Python 3.14.

```sh
npm ci
npm run build
npm test
```

`npm run dev` runs the CLI via tsx; `npm start` runs the built CLI. Tests use
Node's built-in test runner via tsx. Do not start live local or hosted
inference as part of routine validation without explicit authorization.

Run the complete local CI gate set, including for documentation changes:

```sh
npm ci
npm run format:check && npm run check:changelog && npm run typecheck && npm run typecheck:scripts
npm test
npm run check:dev-tools && npm run check:architecture
```

## House conventions

- Write TypeScript, not plain JavaScript. Use ESM and `.js` extensions for
  local imports.
- Use kebab-case filenames, camelCase values, PascalCase types, and
  SCREAMING_SNAKE_CASE constants. Match surrounding Allman braces.
- Every owned code file starts with exactly two comment lines: its
  repo-relative path, then a lowercase untagged purpose phrase. Keep
  shebangs above them.
- Put plain lowercase `//` comments above the code they explain, never
  beside it. Preserve exact symbol casing. Use ASCII `->`.
- Reserve TSDoc for substantial types; avoid comments that repeat code.
- Choose the simplest scoped change. Preserve unrelated files and do not
  add abstractions or configuration without a current repository need.
